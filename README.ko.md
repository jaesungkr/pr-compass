# PR Compass

[English](README.md) · **한국어**

**오픈소스 기여 현황을 GitHub 프로필에서 한눈에 확인하세요.**

프로필 README의 지정된 영역을 자동으로 갱신하는 GitHub Action과 Node CLI입니다.
별도 패키지 설치 없이 열린 PR, 최근 병합된 PR, 리뷰 기록과 현재 HEAD 검사를 정리합니다.
기본적으로 **다른 사용자 또는 조직이 소유한 공개 저장소에 보낸 PR**만 표시합니다.
영어와 한국어 출력을 지원합니다.

## 이미지 대신 README 그대로

최근 병합된 기여를 먼저 보여주고, 제목 링크 아래에 저장소를 간결하게 정리합니다.
진행 중인 PR도 아래에 바로 보이며, 펼침 영역에서 리뷰 기록과 HEAD 검사를 확인할 수 있습니다.

마크다운과 GitHub 지원 HTML만 사용합니다. 글자를 선택할 수 있고 링크를 바로 누를 수 있으며,
좁은 화면에서는 자연스럽게 줄바꿈됩니다. 라이트·다크 테마도 GitHub 기본 스타일을 따릅니다.
생성 이미지, 배지, 외부 호스팅이나 별도 파일이 필요하지 않습니다.

## 프로필에 설치하기

1. `사용자명/사용자명` 저장소의 `README.md`에서 표시할 위치에 아래 마커를 한 쌍 넣습니다.

   ```markdown
   <!-- PR-COMPASS:START -->
   <!-- PR-COMPASS:END -->
   ```

2. [`examples/profile-workflow.yml`](examples/profile-workflow.yml)을 복사해
   `.github/workflows/pr-compass.yml`로 저장합니다. 예제는 검증한 전체 커밋 SHA에
   고정되어 있습니다. 실행 전 해당 코드를 확인하고, 이후 업데이트도 검토한 SHA로 고정하세요.
   기본 조회 대상은 프로필 저장소 소유자입니다. 한국어 표시는 `language: ko`로 설정합니다.

3. 기본 브랜치의 **Actions → Update public PR status → Run workflow**를 실행합니다.
   첫 실행 결과와 README 커밋을 확인하세요. 이후 UTC 기준 6시간마다 23분에 갱신을 요청합니다.

PAT, 별도 계정, 유료 서비스나 저장소 전체 권한 변경은 필요하지 않습니다.
GitHub가 제공하는 단기 `GITHUB_TOKEN`을 사용합니다. 갱신 작업에만 `contents: write`를
지정해 해당 저장소의 README를 커밋합니다. 브랜치 보호나 조직 정책이 쓰기를 막는다면
보호 설정을 해제하거나 권한을 확대하지 말고, 저장소의 검토 절차에 맞게 워크플로를 조정하세요.

Action은 README만 수정합니다. **호출한 워크플로가 README를 커밋합니다.**
마커 바깥의 기존 내용은 보존합니다. 마커가 없거나 중복되거나 순서가 뒤집히면
기존 README를 덮어쓰지 않고 실패합니다.

## Action 입력값

| 입력값 | 기본값 | 설명 |
| --- | --- | --- |
| `username` | 필수 | 조회할 GitHub 사용자명 |
| `readme` | `README.md` | 마커가 한 쌍 들어 있는 파일 |
| `limit` | `5` | 분류별 표시 개수, 1~20 |
| `language` | `en` | `en` 또는 `ko` |
| `include-own` | `false` | 조회 대상 사용자가 소유한 저장소도 포함할지 여부 |
| `token` | `${{ github.token }}` | API 호출 제한에 사용할 GitHub 기본 토큰 |

### 외부 기여의 기준

저장소 소유자를 조회 대상 `username`과 대소문자 구분 없이 비교합니다.
토큰 소유자나 워크플로 실행자를 기준으로 판단하지 않습니다.

- 본인 소유 저장소와 본인 계정으로 포크한 저장소의 PR은 기본적으로 제외합니다.
- 본인 포크에서 다른 사람의 원본 저장소로 보낸 PR은 포함합니다.
- 조직이 소유한 저장소는 포함합니다. 해당 조직의 구성원인지 여부는 조회하지 않습니다.
- 본인 저장소도 포함하려면 Action에 `include-own: 'true'`를 지정합니다.

## 로컬에서 실행하기

Node.js 22 이상이 필요합니다. 검토한 버전의 저장소를 내려받은 뒤 실행하세요.

```sh
node src/cli.mjs --username YOUR_USERNAME --readme /path/to/README.md --limit 5 --language ko
node --test
```

본인 저장소도 포함하려면 `--include-own` 옵션을 추가합니다. 기본값은 `false`입니다.
환경변수 `PR_COMPASS_USERNAME`, `PR_COMPASS_README`, `PR_COMPASS_LIMIT`,
`PR_COMPASS_LANGUAGE`, `PR_COMPASS_INCLUDE_OWN`도 사용할 수 있습니다.
`GITHUB_TOKEN`은 선택사항입니다. 토큰을 명령줄 인자나 커밋에 넣지 마세요.
인증 없이 호출하면 API 사용량 제한이 더 낮습니다.

`readme`를 변경하면 워크플로의 `git add` 경로도 맞춰주세요.
이미지 기반 이전 버전에서 갱신한다면 `assets-dir` 입력값과 기존 생성 폴더
`assets/pr-compass`를 제거하고, 워크플로에서는 README만 커밋하도록 바꿔주세요.

## 표시되는 정보와 한계

- **공개 PR만 조회합니다.** 토큰으로 비공개 저장소에 접근할 수 있어도 비공개 정보는 지원하지 않습니다.
- **PR 상태와 검사는 별개입니다.** 초안·진행 중·병합·닫힘을 검사 상태와 구분합니다.
  실패, 진행 중, 취소·조치 필요, 성공, 중립·생략을 구별하며 검사 결과가 없다고 성공으로 표시하지 않습니다.
- **리뷰 기록은 승인 요건 충족 여부가 아닙니다.** 리뷰어별 최신 유효 결정과 현재 HEAD에 대한
  승인을 구분합니다. 필수 승인 수, 대화 해결 여부와 브랜치 보호 규칙은 추정하지 않습니다.
- **확인한 HEAD를 기준으로 합니다.** 짧은 커밋 링크로 대상 SHA를 표시합니다.
  테스트 병합 커밋 검사는 포함하지 않으며 조회 중에도 PR은 변경될 수 있습니다.
- **조회 범위가 제한됩니다.** 각 분류에서 최근 업데이트순 최대 100건을 가져오고,
  `limit`만큼 표시합니다. 병합 목록은 조회한 표본 안에서 실제 병합일순으로 정렬합니다.
  전체 이력의 최신 병합순을 보장하지 않습니다. 검색 색인 반영이 늦을 수 있고,
  상세 페이지가 잘리면 일부 정보임을 표시합니다.
- **모르는 상태를 정상으로 표시하지 않습니다.** 상세 조회 실패는 조회 불가 또는 일부 정보로
  표시합니다. 검색 실패·불완전 검색·잘못된 입력·마커 오류가 발생하면 이전 README를 유지합니다.
  이때 표시된 관측 시각도 이전 값으로 남습니다.

## 운영 시 알아둘 점

GitHub 예약 실행은 정확한 시각을 보장하지 않으며 지연되거나 누락될 수 있습니다.
기본 브랜치에서 실행되고, 공개 저장소에 60일 동안 활동이 없으면 비활성화될 수 있습니다.
실패 알림이 필요하면 Actions 알림을 확인하고, 필요할 때 수동 실행으로 점검하세요.
실시간 감시 도구가 아니라 주기적으로 갱신하는 스냅샷입니다.

API에는 검색 전용 제한과 추가 호출 제한이 있습니다. 요청은 순차적으로 제한된 범위에서
수행하며 공격적으로 재시도하지 않습니다. 제한에 걸렸다면 권한을 늘리는 대신 다음 실행을 기다리세요.

제거하려면 워크플로 파일을 삭제하세요. 마지막 표시도 없애려면 마커 영역을 함께 지웁니다.
마커만 삭제하고 워크플로를 남기면 이후 실행은 안전하게 실패합니다.

## 개발 및 보안

실행·테스트용 외부 의존성이 없습니다. `node --test`로 API 응답 fixture,
상태 분류, Markdown 이스케이프와 기존 파일 보존 동작을 검사합니다.
CI는 Node 22와 24에서 실행합니다. 실제 토큰이나 비공개 정보를 fixture에 넣지 마세요.
초기 구현과 테스트에 AI의 도움을 사용했습니다.

[보안 및 개인정보 처리](SECURITY.md)를 참고하세요. 기여 시에는 회귀 테스트를 포함하고,
공개 정보만 조회하며 최소 권한으로 동작하는 원칙을 유지해주세요.
